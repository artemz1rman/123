# Регламент технического обслуживания программы «CreditCalc»

*Разработан в рамках учебной практики (вариант 24), ПМ 06
«Сопровождение информационных систем».*

## 1. Общие положения

Настоящий регламент устанавливает порядок технического обслуживания
(ТО) программы «CreditCalc» — консольного кредитного калькулятора.
Обслуживание направлено на обеспечение работоспособности программы,
сохранность пользовательских данных (финансовых планов) и
своевременное обнаружение проблем. Обслуживание выполняет
пользователь программы или ответственный за её сопровождение
специалист.

## 2. Периодичность и состав работ

| Периодичность | Операция |
|---------------|----------|
| Перед каждым сеансом работы | Убедиться, что запускается файл `creditcalc.py` из папки проекта; проверить наличие свободного места на диске (для копий достаточно 1 МБ) |
| После каждого сеанса работы | При необходимости создать резервную копию (пункт меню 7) после сохранения важных планов |
| Еженедельно | Проверить наличие копий в каталоге `backup/`; убедиться, что файлы копий открываются (не «нулевого» размера) |
| Ежемесячно | Выполнить контрольное восстановление из последней копии (пункт меню 8) на тестовых данных; удалить устаревшие планы (пункт 6 → проверка списка) |
| Ежеквартально | Проверить версию Python (`python --version`); при выходе новых версий Python 3.8+ — проверить работоспособность программы; проверить целостность документации в репозитории |

## 3. Резервное копирование и восстановление

1. Резервные копии создаются пунктом меню **7**; архивы имеют имя
   `backup_ГГГГММДД_ЧЧММСС.zip` и хранятся в каталоге `backup/`.
2. Программа автоматически хранит **не более 5 последних копий**;
   удаление более старых копий выполняется программой (ротация).
3. Восстановление выполняется пунктом меню **8**; перед записью
   программа сохраняет текущий файл данных как `plans.json.bak`.
4. Категорически запрещается удалять каталог `backup/` при наличии
   в нём единственной копии данных.

## 4. Типовые неисправности и способы устранения

| Симптом | Вероятная причина | Действие |
|---------|-------------------|----------|
| Программа не запускается | Python не установлен или не добавлен в PATH | Установить Python 3.8+ с python.org, включить «Add to PATH» |
| «Ошибка выполнения операции: [Errno 13]» | Нет прав записи в папку проекта | Запустить из папки с правами на запись (не из Program Files) |
| Планы не сохраняются | Повреждён `data/plans.json` | Восстановить из копии (пункт 8) или удалить повреждённый файл — программа создаст новый |
| «Резервных копий не существует» | Каталог `backup/` пуст | Создать копию пунктом меню 7 |
| Результат в файле неверный | Неверный формат `credit_params.txt` | Проверить, что в файле три строки «ключ: число»; десятичный разделитель — точка или запятая |

## 5. Порядок обновления и сопровождения кода

1. Изменения вносятся в исходный код `creditcalc.py` с сохранением
   стиля комментариев; после изменения выполняется регрессионное
   тестирование по тест-кейсам TC-01…TC-10.
2. Актуальная версия кода и документации хранится в репозитории
   GitHub; перед изменениями создаётся ветка, изменения фиксируются
   коммитами с пояснением.
3. После значимых изменений обновляются README.md, README_EN.md и
   настоящий регламент; версия проекта указывается в README.

## 6. Ответственность

За выполнение периодических операций отвечает пользователь (владелец
данных). За актуальность документации и кода в репозитории отвечает
разработчик. Контроль состояния резервных копий — по чек-листу
раздела 2 не реже одного раза в неделю.

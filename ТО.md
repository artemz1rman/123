## 1. Паспортная часть и общие положения

### 1.1. Назначение документа

1.1.1. Настоящий Регламент технического обслуживания (далее — Регламент) является нормативно-техническим документом, определяющим план, периодичность, содержание работ и зоны ответственности специалистов при поддержании работоспособности информационной системы «CreditCalc» (далее — ИС).

1.1.2. Цели внедрения Регламента:

- минимизация времени простоя ИС и предотвращение сбоев за счёт регулярных профилактических работ;
- обеспечение сохранности данных пользователей — финансовых планов и резервных копий;
- гарантия корректности финансовых расчётов (стабильное соответствие эталонным значениям);
- сокращение времени реакции на инциденты и восстановления после отказов;
- упорядочение и стандартизация действий персонала при выполнении работ по сопровождению;
- обеспечение информационной безопасности данных при эксплуатации ИС.

### 1.2. Область применения

1.2.1. Действие Регламента распространяется на следующие программные и аппаратные средства:

| Категория | Состав |
|-----------|--------|
| Программное обеспечение | Приложение `creditcalc.py` (Python 3.8+, только стандартные библиотеки); файл данных финансовых планов `data/plans.json`; резервные копии `backup/backup_ГГГГММДД_ЧЧММСС.zip` (хранится не более 5 последних копий, ротация автоматическая); страховочная копия `data/plans.json.bak`; файл параметров `credit_params.txt` и результатов `calc_results.txt` |
| Аппаратное обеспечение | Персональный компьютер (рабочая станция): ОС Windows 10/11 или Linux; ОЗУ не менее 2 ГБ; свободное дисковое пространство не менее 100 МБ; стандартные устройства ввода-вывода (клавиатура, мышь, монитор) |
| Сопутствующие компоненты | Интерпретатор Python 3.8+; система контроля версий Git (для сопровождения кода в репозитории GitHub); файловая система хранения данных |

1.2.2. Регламент обязателен к исполнению всеми лицами, выполняющими работы по эксплуатации и сопровождению ИС.

### 1.3. Роли участников

| Роль | Зона ответственности |
|------|----------------------|
| Специалист по сопровождению (администратор ИС) | Планирование и выполнение операций планового ТО (ППР); контроль параметров качества (раздел 3); выполнение внепланового ТО при инцидентах; фиксирование результатов работ |
| Пользователь ИС (владелец данных) | Эксплуатация программы по назначению; создание резервных копий после сохранения важных планов; своевременное информирование специалиста по сопровождению о сбоях и нештатных ситуациях |
| Разработчик ИС | Устранение дефектов программного обеспечения; выпуск исправлений и обновлений в репозиторий; консультирование специалиста по сопровождению |

**Внеплановое (инцидентное) ТО** — аварийные работы, выполняемые по факту возникновения ошибок или отказа ИС. Инициируется при поступлении сообщения о сбое от пользователя либо при обнаружении ошибки специалистом по сопровождению.

### 2.3. Технологические карты внепланового (инцидентного) ТО

Работы выполняются по факту возникновения сбоя. Инициатор — пользователь ИС или специалист по сопровождению.

#### Карта В-1. Восстановление работоспособности при отказе программы

| Параметр | Содержание |
|----------|------------|
| Вид ТО | Внеплановое (инцидентное) |
| Периодичность | По факту инцидента |
| Используемые инструменты | Командная строка, журнал сообщений программы |

**Пошаговый алгоритм выполнения:**

1. Зафиксировать время сбоя, выполняемое действие и полный текст сообщения об ошибке (например, `Ошибка выполнения операции: [Errno 13]`).
2. Перезапустить программу и повторить действие.
3. Если сбой не повторяется — возобновить эксплуатацию.
4. Если ошибка `[Errno 13]` (нет прав записи) — переместить проект в каталог с правами на запись (не Program Files) и повторить операцию.
5. Если программа не запускается — проверить установку Python 3.8+ и включение опции «Add to PATH».
6. При повторении сбоя — зафиксировать условия возникновения и передать инцидент разработчику.

**Ожидаемый результат:** работоспособность ИС восстановлена либо инцидент корректно передан разработчику.

6. Зафиксировать инцидент и объём утраченных данных (при наличии).

**Ожидаемый результат:** данные финансовых планов восстановлены; ИС работоспособна.

## 3. Контроль качества и отчетность

### 3.1. Параметры контроля

Стабильность ИС и качество проведения работ ТО оцениваются по следующим метрикам:

| № | Параметр контроля | Целевое значение | Периодичность оценки | Метод оценки |
|---|-------------------|------------------|----------------------|--------------|
| 1 | Корректность контрольного расчёта | Отклонение от эталона — 0,00 руб. | Ежедневно (П-1) | Сверка с эталонными значениями (500 000 / 18 % / 24 мес.) |
| 2 | Доступность ИС (коэффициент готовности) | ≥ 99 % рабочего времени | Ежемесячно | Учёт простоев и инцидентов |
| 3 | Количество инцидентов (сбоев) | ≤ 2 за месяц | Ежемесячно | Подсчёт зафиксированных инцидентов |
| 4 | Среднее время восстановления после отказа | ≤ 30 минут | По каждому инциденту | Фиксация времени обнаружения и времени восстановления |
